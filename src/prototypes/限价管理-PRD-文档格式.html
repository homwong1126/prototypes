3. 业务对象

3.1 对象关系

限价管理 --- 限价规则（1 --> N），限价申请单 --- 审批记录（1 --> N），限价规则表按车辆版型关联车辆档案；限价申请单通过门店销售ERP号关联门店大区映射（N --> 1）确定所属大区与大区总，通过品牌+产品序列关联条线审批人配置（N --> 1）确定条线审批人。

4. 用户旅程

用户旅程图如下：

用户旅程流程说明如下：

  1. 门店销售在销售/订单流程中对车辆配车并保存订单。
  2. 系统根据库存车辆定义字段判断车辆性质：常规车或非常规车（冰雹车等）。
  3. 系统读取限价规则表，按车辆车型/版型匹配当前限价（综合毛利限价及各级审批额度）。
  4. 系统按审批规则判定是否触发审批及所需审核级别：预估综合毛利 ≥ 综合毛利限价不触发；预估毛利为负值走集团审核；预估毛利低于限价按降幅命中层级配置金额判定。
  5. 若触发审批，系统判定所需审核级别并自动生成限价申请单，同时按门店销售ERP号带出所属大区、大区总及条线审批人。
  6. 订单保存后弹出 toast：订单已触发限价审批，通过限价管理-限价申请跟踪审批进度。
  7. 限价申请单按 大区审核 → 条线审核 → 门店审核 → 集团审核 逐级流转。
  8. 大区审核节点：系统按门店-大区映射表，以门店所属大区过滤单据，仅该大区大区总可见并审批。示例：郑州盈丰（ERP号 3059）属河南一区，则 3059 门店的限价申请单均由河南一区大区总王芬审批；安阳盈丰属河南二区，其单据由河南二区大区总胡军召审批。
  9. 条线审核节点：系统按品牌+产品序列定位对应的门店运营销售支持（条线审批人）进行单据审批。示例：C网/H网由刘邓淅审批，E网/R网由章登廷审批，Q网由马兆初审批，捷途/星途由周彬审批，iCAR 由陈核锋审批。
  10. 各级审核人员进入限价申请列表，仅可见与自己职责匹配的待审核单据，执行通过或驳回。
  11. 任一级驳回则逐级退回上一审批节点；全部通过则申请单状态为“已通过”。
  12. 申请单状态为“已通过”后，订单录入流程-【新车开票】方可继续执行。

注：若车辆版型在限价规则表中无匹配数据，则不生成限价申请单，默认该订单预估综合毛利大于综合毛利限价（视为无需限价审批）。

5. 数据流图

数据流图如下：

数据流图流程说明如下：

  1. 库存管理提供车辆档案，包含车辆定义字段（车辆性质类型）。
  2. 限价规则表维护各车型限价及大区/条线/门店/集团审批额度。
  3. 订单配车保存时，系统按车辆 VIN/版型从车辆档案读取车辆性质。
  4. 系统按车型版型匹配限价规则表，获取综合毛利限价与各级审批额度。
  5. 系统按审批规则判定是否触发及所需审核级别：预估综合毛利 ≥ 限价不触发；预估毛利为负值 → 集团审核；预估毛利低于限价按降幅命中层级配置金额。
  6. 若触发限价，系统创建限价申请单并记录订单关联，按门店-大区映射带出所属大区与大区总，按品牌+产品序列带出条线审批人。
  7. 限价申请单进入审批流程：大区审核单据按门店所属大区过滤后由对应大区总处理，条线审核单据按品牌+产品序列路由至对应门店运营销售支持，门店/集团审核逐级流转；审核结果回写申请单状态。
  8. 申请单“已通过”后，订单录入流程-【新车开票】读取通过状态放行。
  9. 限价规则表支持单独新增与批量导入方式维护车辆限价及审批额度。
  10. 门店-大区映射表维护门店（ERP号）与所属大区、大区总对应关系，是大区审核单据过滤的数据来源；条线审批人配置表维护品牌+产品序列与门店运营销售支持的对应关系，是条线审核路由的数据来源。

6. 状态机

状态机图如下：

限价申请单关注的状态节点如下：

  • 未触发：预估综合毛利 ≥ 综合毛利限价或版型无匹配，无需生成限价申请单。
  • 待审核：限价申请单已生成，正在审批流转中，视为有效申请单；单据已按门店带出所属大区、大区总与条线审批人。
  • 逐级审批中：申请单正在按大区 → 条线 → 门店 → 集团流转；大区节点单据按门店所属大区过滤至对应大区总，条线节点单据按品牌+产品序列路由至对应门店运营销售支持。
  • 已通过：所有需审批级别均已通过，订单可进入【新车开票】。
  • 已驳回：任一级审批驳回并逐级退回，视为有效申请单（当前不可继续新车开票）。

审核流转关系：

  • 未触发 → 待审核：预估综合毛利 < 综合毛利限价（含负值）且车型/版型匹配，生成申请单，同时确定所属大区/大区总与条线审批人。
  • 待审核 → 逐级审批中：申请单进入大区审核，单据按门店所属大区过滤，仅该大区大区总可见可审。
  • 逐级审批中（大区通过）→ 条线审核：单据按品牌+产品序列路由至对应门店运营销售支持（条线审批人）。
  • 逐级审批中 → 已通过：最深需审批级别通过。
  • 逐级审批中 → 已驳回：任一级驳回。
  • 已驳回 → 待审核：驳回后重新提交，恢复到待审核流转。
  • 已通过 → 新车开票：订单录入流程放行执行。

注：同一辆车同一时间仅允许存在一条有效限价申请单（待审核、已驳回视为有效），系统禁止重复生成多条申请单。限价流程必须为“已通过”，订单录入流程-【新车开票】方可继续执行。

7. 功能原型

原型来源：盈丰运营管理平台限价管理（src/prototypes/price-limit-apply、price-limit-list、共享限价逻辑 shared/price-limit）。

所属模块：限价管理

本页面依据限价管理原型、订单配车联动规则和库存车辆性质判定需求生成。

核心业务规则：

  • 通过库存管理车辆定义字段判定车辆为常规车或非常规车，除常规车外的性质类型均视为非常规车。
  • 按车辆车型/版型匹配限价规则表，获取综合毛利限价与各级审批额度。
  • 审批规则：
    1. 预估综合毛利 ≥ 综合毛利限价：无需审批，不生成限价申请单。
    2. 预估综合毛利为负值：走全部审批，需审核级别固定为集团审核。
    3. 预估综合毛利 < 综合毛利限价（且非负）：按降幅 = 综合毛利限价 - 预估综合毛利，命中层级配置金额判定需审核级别。
    • 0 < 降幅 ≤ 大区审核额度：大区审核
    • 大区额度 < 降幅 ≤ 大区额度 + 条线额度：条线审核
    • 条线额度 < 降幅 ≤ 条线额度累计 + 门店额度：门店审核
    • 超出门店累计额度：集团审核
  • 审批按 大区 → 条线 → 门店 → 集团 逐级流转，驳回逐级退回。
  • 审批人定位：大区审核单据按申请单门店所属大区过滤，由该大区的大区总审批；条线审核单据按品牌+产品序列定位门店运营销售支持（条线审批人）审批。
  • 触发限价后订单须待申请单"已通过"才能进入【新车开票】。
  • 同一辆车仅允许一条有效限价申请单（待审核/已驳回均视为有效）。

11. 业务规则总结

11.1 核心业务规则

  1. 车辆性质判定：通过库存管理里的车辆定义字段判定车辆属于常规车还是冰雹车等非常规车性质类型；除常规车外，其他性质的车均视为非常规车。
  2. 限价匹配：判定车辆性质后，读取限价规则表中车辆车型数据，通过车辆版型匹配对应的限价审批。
  3. 审批触发与级别判定：
    1. 预估综合毛利 ≥ 综合毛利限价：无需审批，不生成限价申请单。
    2. 预估综合毛利为负值：走全部审批，需审核级别固定为集团审核。
    3. 预估综合毛利 < 综合毛利限价（且非负）：降幅 = 综合毛利限价 - 预估综合毛利，降幅 > 0 触发限价审批，按命中层级配置金额判定需审核级别。
    • 示例：综合毛利限价 3000，预估毛利 1500（降幅 1500），大区审核额度 1000、条线 1000、门店 500、集团不设上限。降幅 1500 > 大区额度 1000 → 条线审核；条线累计额度 2000 ≥ 1500，则需审核级别为条线，条线审核通过后流程结束。依此类推至门店、集团。
    • 负向示例：综合毛利限价 -5000，预估综合毛利 -4999，因预估毛利 -4999 ≥ 限价 -5000 不触发审批。
    • 边界示例：预估综合毛利正好为 0 时不属于负值；当降幅命中某级额度且预估毛利为负时按"负值走集团审核"处理。
  4. 订单配车联动：订单配车保存后，弹出 toast：订单已触发限价审批，通过限价管理-限价申请跟踪审批进度；系统自动生成限价申请单，按 大区审核 → 条线审核 → 门店审核 → 集团审核 流转。
  5. 大区审核人定位：大区审核按门店所属大区进行单据过滤——依据门店-大区映射表，以申请单门店销售ERP号确定所属大区及大区总，该门店的限价申请单均由该大区大区总审批。示例：郑州盈丰（ERP号 3059）属河南一区，3059 的限价申请单均由河南一区大区总王芬审批。
  6. 条线审核人定位：条线审核按品牌+产品序列定位审批人——由品牌+产品序列对应的门店运营销售支持进行单据审批。示例：C网/H网→刘邓淅，E网/R网→章登廷，Q网→马兆初，捷途/星途→周彬，iCAR→陈核锋。
  7. 驳回退回：任一级驳回则逐级退回上一审批节点。
  8. 无匹配数据特殊场景：车辆版型无匹配数据时，无需生成限价申请单，默认订单预估综合毛利大于综合毛利限价。
  9. 开票放行：触发限价流程后，限价流程必须为"已通过"状态，订单录入流程-【新车开票】方可继续执行。
  10. 单条有效申请单：同一辆车只允许存在一条有效限价申请单；【待审核】【已驳回】状态均视为有效申请单，不可出现多条申请单。

11.2 数据校验规则

  • 预估综合毛利 ≥ 综合毛利限价时不触发审批；预估综合毛利为负值走集团审核；预估综合毛利 < 综合毛利限价（且非负）时按降幅命中层级配置金额触发审批并生成限价申请单。
  • 驳回时审核意见为必填项。
  • 同一车辆存在有效限价申请单（待审核/已驳回）时，禁止重复生成。
  • 新车开票前，限价流程状态必须为"已通过"。
  • 常规车型新增限价规则时，年份、月份必填；非常规车型（冰雹车等）无需维护年份、月份。
  • 限价申请单生成时必须成功匹配门店-大区映射（门店销售ERP号 → 所属大区/大区总）；条线审核前必须成功匹配条线审批人（品牌+产品序列 → 门店运营销售支持），匹配缺失时提示配置缺失并阻止对应节点流转。

11.3 限价规则维护与导入

  • 通过单独新增车辆信息及审批权限额度维护限价规则。
  • 同样支持通过批量导入方式新增车辆限价信息及审批权限额度。
  • 选择常规车型时，需选择年份、月份进行维护；选择除常规车外任意一种类型（非常规车），则无需选择年份、月份进行维护。

11.4 权限控制

  • 门店销售：提交订单并触发限价申请，可查看限价申请列表与详情。
  • 大区总：按门店所属大区过滤单据，仅对其管辖大区内的门店限价申请单进行审批（如河南一区大区总王芬审批郑州盈丰等河南一区门店单据）。
  • 条线审批人（门店运营销售支持）：按品牌+产品序列过滤单据，仅对其负责条线的限价申请单进行审批（如刘邓淅审批C网/H网单据、周彬审批捷途/星途单据）。
  • 门店/集团审核人员：按对应审核级别对门店、集团级别的限价申请单进行通过或驳回操作。
  • 销售运营/财务：维护限价规则表，维护审批权限额度，支持批量导入。
  • 财务：查看限价申请列表与详情，跟踪审批进度。

12. 第二阶段迭代需求：飞书消息通知与 H5 审核（待计划）

12.1 需求背景

限价申请单生成时，系统需实时通过飞书机器人向对应的审批人员（大区总、条线审批人、门店/集团审核人）发送消息通知，通知内容包含申请单号、流程模块、当前审批人、提交时间等信息。审批人员可通过消息中的超链接直接跳转至 H5 审核页面，进行对应节点的审批操作，无需重复登录。

12.2 飞书消息推送

12.2.3 飞书通知配置

  • 飞书机器人应用接入：通过盈丰运营管理平台的飞书应用集成，向指定的飞书部门/用户群组发送消息。
  • 机器人权限：需具备向内部部门、审核人员个人账号发送消息的权限。
  • 失败重试：消息发送失败时，应进行 3 次重试；重试仍失败则记录告警日志，便于运维跟踪。
  • 消息存档：所有发送的消息应在系统内记录消息发送时间、接收方、内容等信息，便于事后追溯与审计。

12.3 H5 审核页面

12.3.1 H5 页面概述

H5 审核页面是限价管理 PC 端审核页面的移动版本，支持在手机浏览器上进行限价申请单的审批操作。页面通过 SSO 机制实现免登录访问，用户点击飞书消息链接后自动跳转至该页面。

12.3.2 H5 页面 URL 结构

H5 审核页面 URL 包含以下参数：

  • /h5/price-limit-apply/review?id=XJ3356202609010001&sso_token=xxx&redirect_uri=xxx
  • id：申请单号（必填）
  • sso_token：SSO 令牌，由飞书传递，用于免登录认证（必填）
  • redirect_uri：审批完成后的重定向地址，通常为审批列表页或飞书对话（可选）

12.3.3 H5 审核页面功能

功能区功能说明与 PC 端区别
申请单信息只读展示：申请单号、门店、大区、VIN码、车辆信息等与 PC 端一致
限价信息只读展示：综合毛利限价、预估综合毛利、需审核级别、降幅说明与 PC 端一致
审核信息展示当前审核级别、创建时间；需审核时提供审核意见输入框与 PC 端一致
底部操作返回、驳回、通过三个按钮界面布局适配移动端（按钮更大、间距更宽），操作逻辑与 PC 端保持一致
响应式设计自适应手机、平板屏幕宽度，确保内容清晰可读PC 端无此需求

12.3.4 H5 页面审批逻辑

  • 审批规则与 PC 端保持一致：预估毛利 ≥ 限价显示"无需审批"（只读不可操作）；预估毛利 < 限价按规则判定需审批级别；预估毛利为负值固定集团审核。
  • 审批人定位与 PC 端保持一致：大区审核按门店所属大区过滤，条线审核按品牌+产品序列路由，门店/集团审核逐级流转。
  • 驳回时审核意见为必填项，同 PC 端逻辑。
  • 审批操作触发后，系统同时更新数据库、回传消息至飞书（通过 bot 在原消息下方追加审批结果）、重定向至 redirect_uri（如有）或返回审批列表。

12.3.5 SSO 集成

  • SSO 认证：飞书消息链接中包含 sso_token 参数，H5 页面接收该 token 后，无需用户重新登录即可访问。
  • Token 验证：H5 页面后端需验证 sso_token 的有效性（签名、过期时间等），确保安全。
  • 用户身份获取：通过 token 解析得到用户身份信息（工号、姓名、部门等），用于权限校验、审批人定位。
  • 会话管理：SSO 认证通过后，可在浏览器 cookie 中设置会话 token，确保后续操作无需重复验证。

12.4 消息流转示例

以下为完整的消息推送与审批流转示例：

  1. 申请单生成阶段：门店销售提交订单配车，系统生成限价申请单 XJ3356202609010001（门店ERP号3356，预估毛利1200，限价3000，降幅1800，需大区审核）。
  2. 大区审核通知：系统向该门店所属大区（河南一区）的大区总（王芬）发送飞书消息，消息标题为 XJ3356202609010001 + 3356，当前审批人为 王芬，提交时间为 2026-09-01 10:08:00。王芬点击消息中的"立即审核"按钮，跳转至 H5 审核页面 /h5/price-limit-apply/review?id=XJ3356202609010001&sso_token=xxx，进行审核。
  3. 大区审核通过：王芬点击"通过"按钮，申请单进入条线审核阶段。系统向条线审批人（C网/H网由刘邓淅审批）发送飞书消息，当前审批人为 刘邓淅。
  4. 条线审核驳回：刘邓淅审核后点击"驳回"，填写意见"降价幅度超出权限范围"。系统将申请单状态改为"已驳回"，向门店销售发送飞书消息告知驳回原因，消息中提供重新提交链接。
  5. 重新提交：门店销售调整车辆信息后重新提交订单，系统生成新的申请单并重复流程。
