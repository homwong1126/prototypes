# 维修工单管理 - 待完工编辑功能实现总结

## 📋 需求回顾

用户需求：
1. 列表 mock 一条待完工状态的数据
2. 有编辑、完工按钮
3. 操作列按钮超过2个通过"更多"按钮展示
4. 点击编辑可对维修工单进行编辑
5. 对维修项目/配件编辑按钮去除，保留删除按钮
6. 项目已派工不可调整及删除
7. 配件已领料不可调整及删除
8. 如新增项目及配件，则记录增项标识

### 3. 编辑功能实现

**编辑规则**：
| 类型 | 状态 | 可编辑 | 可删除 | 标识 |
|------|------|--------|--------|------|
| 维修项目 | 已派工 | ❌ | ❌ | 🔒 已派工 |
| 维修项目 | 未派工 | ✅ | ✅ | - |
| 维修项目 | 新增 | ✅ | ✅ | 🟡 增项 |
| 配件 | 已领料 | ❌ | ❌ | 🔒 已领料 |
| 配件 | 未领料 | ✅ | ✅ | - |
| 配件 | 新增 | ✅ | ✅ | 🟡 增项 |

**视觉标识**：
- 已派工/已领料：带锁图标标签
- 增项：浅黄色底色 + 橙色"增项"标签

**操作流程**：
1. 点击"编辑"进入编辑模式
2. 表格变为可编辑状态
3. 已派工/已领料项只读
4. 未派工/未领料项可编辑
5. 新增项自动标记增项
6. 费用实时计算
7. 保存或取消

### 4. 数据模型更新

**PartItem 新增字段**：

### 5. 业务逻辑

**handleUpdateItems 方法**：

- 更新时间戳

**编辑状态管理**：
- `canEditOrder`：是否允许编辑
- `isEditing`：是否处于编辑模式
- `editingRepairItems`：维修项目编辑副本
- `editingParts`：配件编辑副本
