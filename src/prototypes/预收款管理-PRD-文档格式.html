4. 用户旅程

用户旅程流程图如下：

  1. 收银员或服务顾问进入预收款管理页面。
  2. 点击"新增预收款"按钮，打开预收款登记表单。
  3. 通过车辆搜索功能，输入车牌号、车架号、客户姓名或手机号搜索车辆信息。
  4. 选择匹配的车辆后，系统自动回填客户姓名、手机号、车牌号、车架号和车系信息。
  5. 若未搜索到车辆，可手动输入车牌号和车架号。
  6. 填写维修委托书号、预收金额、支付方式等必填信息。
  7. 保存后生成预收单号，状态为"待抵扣"，可用余额等于预收总额。
  8. 在维修结算时，系统自动关联预收款记录。
  9. 系统计算本次可抵扣金额 = min(预收可用余额, 客户自费应收)。
  10. 仅抵扣客户自费部分，保修和保险应收不参与预收冲抵。
  11. 若预收款大于客户自费应收，剩余金额可选择保留为客户预存余额或发起退款。
  12. 抵扣完成后，更新预收款状态为"部分抵扣"或"已抵扣"。
  13. 若需退款，进入退款处理页面，发起退款申请。
  14. 退款完成后，更新状态为"已退款"。

5. 数据流图

数据流图如下：

  1. 用户在预收款台账页面查询预收款记录。
  2. 系统加载预收款列表，展示预收单号、客户、车牌号、预收金额、已抵扣、可用余额、状态等信息。
  3. 用户点击"新增预收款"，系统打开登记表单。
  4. 用户输入车辆搜索关键词，系统查询车辆档案库，返回匹配的车辆候选列表。
  5. 用户选择车辆后，系统自动填充客户和车辆信息到表单。
  6. 用户填写维修委托书号、预收金额、支付方式等信息并保存。
  7. 系统生成预收单号，创建预收款记录，初始状态为"待抵扣"。
  8. 系统记录收款流水，类型为"收款"。
  9. 在维修结算环节，系统查询该客户的可用预收款余额。
  10. 系统识别结算单中的客户自费应收金额。
  11. 系统计算本次可抵扣金额，仅抵扣客户自费部分。
  12. 用户确认抵扣方案后，系统更新预收款的已抵扣金额和可用余额。
  13. 系统记录抵扣流水，类型为"抵扣"。
  14. 若有剩余余额且用户选择退款，系统创建退款申请。
  15. 退款完成后，系统记录退款流水，类型为"退款"，并更新预收款状态。

6. 状态机

状态机图如下：

预收款管理关注的状态节点如下：

  • 待抵扣：预收款已登记，尚未用于结算抵扣，可用余额等于预收总额。
  • 部分抵扣：预收款已部分用于结算抵扣，仍有可用余额。
  • 已抵扣：预收款已全部用于结算抵扣，可用余额为零。
  • 可退款：预收款有可用余额，且满足退款条件（如客户取消维修、配件未到货等）。
  • 已退款：预收款余额已全部或部分退还给客户。

状态流转关系：

  • 待抵扣 → 部分抵扣：预收款部分用于结算抵扣，仍有剩余余额。
  • 待抵扣 → 已抵扣：预收款全部用于结算抵扣，余额为零。
  • 部分抵扣 → 已抵扣：剩余预收款全部用于后续结算抵扣。
  • 待抵扣 → 可退款：客户取消维修或其他原因需要退款。
  • 部分抵扣 → 可退款：剩余余额需要退款。
  • 可退款 → 已退款：退款申请完成，余额退还给客户。
  • 部分抵扣 → 部分抵扣：多次结算抵扣，每次抵扣后仍有余额。

7. 功能原型

原型来源：`prototype-workbench/src/prototypes/prepayment-management`

所属模块：预收款管理

本页面依据预收款管理原型、维修结算联动规则和财务管理需求生成。

核心业务规则：

  • 预收款仅允许抵扣客户自费部分，不抵扣保修和保险应收。
  • 本次可抵扣金额 = min(预收可用余额, 客户自费应收)。
  • 当预收款大于客户自费应收时，剩余金额可保留为客户预存余额或发起退款。
  • 支持通过车牌号、车架号、客户姓名或手机号搜索车辆，自动回填客户和车辆信息。
  • 未搜索到车辆时，车牌号和车架号仍允许手动输入。

11. 业务规则总结

11.1 核心业务规则

  1. 抵扣规则：预收款仅允许抵扣客户自费部分，不抵扣保修和保险应收。本次可抵扣金额 = min(预收可用余额, 客户自费应收)。
  2. 超额处理：当预收款大于客户自费应收时，剩余金额可选择保留为客户预存余额或发起退款。
  3. 状态流转：预收款状态按照 待抵扣 → 部分抵扣 → 已抵扣 或 待抵扣/部分抵扣 → 可退款 → 已退款 流转。
  4. 车辆搜索：支持通过车牌号、车架号、客户姓名或手机号搜索车辆，自动回填客户和车辆信息。未搜索到车辆时，车牌号和车架号仍允许手动输入。
  5. 流水追踪：所有收款、抵扣、退款操作均记录流水，包含操作人、时间、金额、支付方式和摘要，用于财务对账和审计。

11.2 数据校验规则

  • 预收金额必须大于0。
  • 维修委托书、客户姓名、手机号为必填项。
  • 抵扣金额不能超过预收可用余额。
  • 抵扣金额不能超过客户自费应收金额。
  • 退款金额不能超过预收可用余额。

11.3 权限控制

  • 收银员：可新增预收款、查看预收款列表和详情、发起退款。
  • 服务顾问：可查看预收款列表和详情、查看结算抵扣联动、确认抵扣方案。
  • 结算岗：可查看预收款列表和详情、查看结算抵扣联动、确认抵扣方案。
  • 财务人员：可查看所有预收款数据、收款流水、退款处理台账，可导出数据。
  • 审计人员：可查看收款流水，用于审计追踪。

说明：本 PRD 基于预收款管理原型（prototype-workbench/src/prototypes/prepayment-management）及维修结算联动规则整理生成。核心业务逻辑为：预收款仅抵扣客户自费部分，当预收款大于客户自费应收时，剩余金额可保留为客户预存余额或发起退款。支持通过车辆搜索自动回填客户和车辆信息，所有资金变动均记录流水用于财务对账。
