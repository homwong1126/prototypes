限价申请（移动版） price-limit-apply-copy

本文档是用户与 Agent 围绕当前原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：为“大客户营销平台 — 限价管理”提供移动端轻量审核闭环，与桌面端 price-limit-apply 同规则、同数据；承接消息提醒入口，完成申请单浏览、筛选、按计算级别审核、详情只读查看。
  • 使用场景：门店/大区/条线/集团审核人在手机端接收限价申请待办提醒；快速按状态检索；在列表中识别“需审核级别”标签；进入审核页完成通过/驳回；已审单据仅只读查看。
  • 当前表达：React 原型 src/prototypes/price-limit-apply-copy/index.tsx 已实现 4 视图 message / list / review / detail，含双形态列表（桌面 12 列表格 + 移动卡片网格）、审核级别自动计算、吸底操作区与只读详情页。

事实与输入

用户确认事实

  • 审核级别：大区 / 条线 / 门店 / 集团；权限额度 1000 / 2000 / 3000 / ∞ 元；降幅 drop = 限价 - 预估。
  • 审核规则 computeMarginApproval(limit, estimated)：① estimated ≥ limit → ok / 无需审批；② estimated < 0 → negative / 集团；③ 否则按 drop 1000/2000/3000 逐级判定，大区为起点，超出即升级。
  • 状态：待审核 / 已通过 / 已驳回；待审核可审核（按钮文案为计算出的级别如“大区审核”），已审仅“查看”。
  • 申请单核心字段：单号 id（如 XJ3356202609010001）、门店 ERP storeErpNo、门店名、车辆信息（VIN/SAP物料/物料/品牌/系列/车系/车型/年款/动力/版型/内外饰色/采购订单类型/采购类型/生产日期/入库时间/采购价）、限价 marginLimit、预估 estimatedMargin、createdAt / approver / approvedAt / reviewComment。
  • 文案：驳回时“审核意见”必填；吸底操作区按钮：驳回（红）/ 通过（蓝）；顶部面包屑 限价申请 / 审核 | 详情。

当前假设

  • 移动端列表中“需审核级别”仅展示标签，不提供独立筛选入口（与桌面筛选器差异为有意简化，待确认是否需加回）。
  • 消息流中非限价模块（如“返利资金划转”）仅占位展示，不做真实跳转；首条限价消息可直进审核并记忆 reviewOrigin=message。

原型范围

本次呈现

  • 消息页 message：机器人消息流（4 条示例），限价申请卡片可点进审核，记忆返回来源。
  • 列表页 list：双形态 — 桌面 pla-table-container 表格（悬停高亮）与移动 pla-mobile-cards 卡片网格（2 列、金额低于限价标红）；筛选区：关键字（申请单号/VIN）、审核状态、需审核级别（桌面端保留选择器）；空状态“暂无符合条件的数据”。
  • 审核页 review：申请单信息（单号只读带锁）+ 车辆信息卡（2 列网格，VIN 高亮、采购价橙色）+ 限价信息三卡（限价/预估/级别，移动端 2+1 布局）+ 审核信息（状态/人/时间/意见 textarea，驳回必填）+ 吸底操作（驳回/通过）、顶部返回头。
  • 详情页 detail：申请单/车辆/限价/审核信息只读展示，复用审核页卡片，按钮仅“返回列表”。
  • 全局：四级级别标签色 大区蓝 / 条线靛 / 门店橙 / 集团紫、状态徽章、Toast 成功/失败、标注路由 message/list/review/detail 联动。

本次不呈现

  • 真实后端、权限鉴权、分页/批量操作、导出、限价规则编辑联动。
  • 消息推送与已读状态持久化；全量移动手势与离线。
  • 除 style.css 覆盖外的独立 Design System 定制。
