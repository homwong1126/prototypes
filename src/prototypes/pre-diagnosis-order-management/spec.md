# 预诊单管理高保真原型规格说明

## 1. 原型目标

基于现有预诊模板配置能力，设计并实现门店服务顾问使用的预诊单管理高保真原型，用于在维修工单正式创建或派工前完成客户问题识别、车辆信息确认、预约单关联、通用技术检查、异常判断、故障分类选择、附件上传、深度诊断记录、技师记录与转工单故障现象沉淀。

原型整体布局、控件密度、字体、配色和后台管理页气质参考 `src/prototypes/repair-workorder-m02`。

## 2. 页面范围

### 2.1 预诊单列表

用于查看、筛选和进入预诊单。

核心内容：

- 顶部业务页签：预诊单列表、创建预诊单、预诊单详情
- 状态节点：全部、待预诊、待转工单、已完成，呈现在“数据列表”标题下方，样式与维修工单列表状态 Tab 保持一致
- 列表内容顶部仅保留面包屑，不额外展示英文眉标与页面标题说明
- 查询条件：参考 `src/prototypes/repair-workorder-m02` 的上下结构查询区，采用 5 列栅格排布；字段包括车牌号、VIN码、客户、状态、服务顾问、创建日期
- 数据表格：预诊单号、状态、车牌号、VIN、客户姓名、预约单号、问题分类、故障现象、服务顾问、创建时间、预计完成时间、操作
- 行操作：查看、编辑；已完成状态不展示编辑按钮

### 2.2 创建预诊单

创建流程为统一入口，不区分“有预约单”和“无预约单”。

车辆查询方案参照维修工单管理：

- 在“车主车辆信息”卡片中提供车牌号输入框和主按钮“查询”
- 同一行提供“或输入 VIN 查询”分隔文案
- 提供 VIN 输入框和“按 VIN 查询车辆”按钮
- 点击“按 VIN 查询车辆”打开车辆查询弹窗
- 车辆查询弹窗包含两个 Tab：车辆查询、车辆精确查询
- 车辆查询 Tab 字段：VIN、车牌号
- 车辆精确查询 Tab 字段：VIN、发动机后 6 位
- 弹窗结果表格字段：VIN、车辆用途、车辆状态、车系、里程、车牌号、发动机号、客户姓名
- 选择车辆并确认后，回填车主车辆信息

预约单关联规则：

- 车辆查询或回填后自动匹配预约单
- 车主车辆信息采用维修工单管理同款主信息带：左侧展示创建预诊单、车牌号 / VIN、车型、保修到期日、最近进厂、最近里程；右上角固定展示车辆动作按钮
- 在车辆动作按钮区固定展示“关联预约单”，命中预约单时展示数量徽标
- 点击后打开车辆信息弹窗并定位到关联预约单内容，仅保留第一条匹配预约单数据，展示预约单号、预约来源、车牌号、VIN、客户姓名、手机号、预约时间、预约类型、状态
- 选择预约单并点击“关联选中预约单”后，将预约单基础信息带入预诊单，预约来源示例统一使用 apollo
- 未命中预约单时，不展示独立无预约入口，继续在同一创建页面手工补录客户、车辆和问题信息

创建页主要模块：

- 页面顶部仅保留“售后服务 / 预诊单管理 / 创建预诊单”面包屑，不展示创建页标题 Hero、英文说明或顶部右侧保存 / 提交预诊按钮
- 车主车辆信息：车牌 / VIN 查询、车辆主信息带、客户车辆信息回填；车辆信息动作区按维修工单管理按钮位置展示“关联预约单 / 委托书履历 / 车辆权益 / 服务活动 / 品质改善 / 维修建议 / 车主车辆信息变更”
- 预约单关联：命中后仅在车辆主信息带展示预约单号链接，不展示独立关联状态或预约单摘要条
- 委托书履历：点击后弹出当前车辆历史委托书摘要与列表，支持将历史问题带入客户问题描述
- 车辆权益：点击后在车辆信息弹窗中展示保养套餐、延保产品、代金券、充值卡四类权益摘要
- 服务活动 / 品质改善：点击后在车辆信息弹窗中展示服务活动与品质改善两类待确认项目，默认勾选；确认后更新按钮待处理数量
- 维修建议：点击后在车辆信息弹窗中展示维修建议列表，默认勾选；确认后更新按钮待处理数量并带入预诊问题描述
- 车主车辆信息变更：点击后弹出客户姓名、手机号、车牌号、VIN、车型表单，确认后回填车辆信息区
- 预诊基础信息下方不展示预约单来源、预约时间和状态摘要条；关联后的预约单仅在车辆主信息带中以预约单号链接呈现，点击后展示预约单详情弹窗
- 预诊基础信息：服务顾问、服务方式、进厂里程、预计完成时间、预诊来源；服务方式仅保留自驾到店、救援、取车到店
- 客户问题：布局在预诊基础信息下方，不采用左右分栏；包含客户描述、问题分类、故障现象、紧急程度
- 通用技术检查与深度诊断：先完成接待区外观与内外饰快速环检，以及车内（低压上电）检查，通过“是否异常”Radio 判断是否进入故障分类和深度诊断；说明文案通过图标点击弹出
- 异常处理：接待区和车内（低压上电）检查下方均独立展示一级分类、二级分类、故障现象和附件上传；仅在任一检查分组的一级分类、二级分类、故障现象均选定后展示对应深度诊断步骤指导；附件支持 jpeg / jpg / png / pdf，单个文件不超过 50M
- 诊断过程与技师记录：记录通用检查、异常分类、深度诊断、证据材料、技师过程说明、深度诊断照片和最终诊断结论
- 动态吸顶操作条：保存、提交预诊

### 2.3 预诊单详情

用于查看已创建预诊单的完整信息和流转状态。

核心内容：

- 顶部摘要：预诊单号、状态、关联预约单、客户、车辆、服务顾问
- 流程进度：已创建、车辆确认、预约关联、诊断检查、待转工单、已完成；样式参照维修委托书详情页状态节点轴，采用圆形节点、横向连线、已完成 / 当前 / 未到达状态区分
- 基础信息：客户、车辆、预约单、服务方式、进厂里程、创建时间
- 客户问题、通用检查与深度诊断：展示问题分类、故障现象、客户描述、紧急程度、通用技术检查是否异常、一级分类、二级分类和附件数量
- 通用技术检查：展示接待区外观与内外饰快速环检项目、车内（低压上电）检查项目
- 深度诊断：展示根据一级分类、二级分类、故障现象匹配出的步骤指导、操作说明、关键判断点和检查结果
- 诊断过程：展示通用检查、异常标签、深度诊断的执行时间、阶段、状态、执行人、执行动作、发现问题和证据材料
- 技师记录：展示技师过程记录、深度诊断照片、最终诊断结论、转工单建议和转工单故障现象
- 处理记录：创建、关联预约、保存检查、提交、转工单等时间线

## 3. 状态设计

预诊单状态：

- 待预诊：已创建，等待服务顾问执行检查
- 待转工单：预诊完成，等待创建维修工单
- 已完成：已完成预诊或已完成后续转工单处理

预约关联状态：

- 未查询：尚未执行车辆查询
- 未命中：已查询车辆但未找到预约单
- 待关联：命中预约单但未确认关联
- 已关联：已确认预约单并带入基础信息

## 4. 交互规则

1. 创建预诊单时，入口始终只有一个：车牌号 / VIN 查询车辆。
2. 车牌号查询优先在主卡片完成；VIN 查询沿用维修工单管理的“按 VIN 查询车辆”弹窗。
3. VIN 输入应转为大写展示；车辆精确查询要求 VIN 和发动机后 6 位同时填写。
4. 选择车辆后自动回填车辆与客户基础信息。
5. 若车辆命中预约单，仅展示可关联预约单，不强制关联；用户可选择关联或继续手工填写。
6. 关联预约单后，预约单号、客户姓名、手机号、车牌号、VIN、车型、预约时间、服务方式、客户描述带入创建表单。
7. 未命中预约单时，同页继续填写，不出现“无预约单创建”特殊入口。
8. 服务方式与维修工单管理对齐，但预诊创建页仅保留自驾到店、救援、取车到店；不展示上门服务和技术万里行。
9. 创建页顶部不展示“一个入口完成车牌 / VIN 查询；系统自动匹配预约单，未命中则同页手工补录”说明文案。
10. 诊断过程先执行通用技术检查：接待区外观与内外饰快速环检，检查四角高低、灯光外观、外饰件、轮胎、内饰和储物件；同时执行车内（低压上电）检查，检查场景为车内（低压上电，不踩刹车），包含 12V蓄电池静态检查、诊断仪全车扫描、座舱与车身电气功能测试。
11. 通用技术检查通过“是否异常”Radio 记录是 / 否。
12. 选择“是”后，接待区和车内（低压上电）检查分组下方分别展示一级分类、二级分类、故障现象和附件上传；选择“否”后，不进入故障分类和深度诊断。
13. “先完成通用技术检查，再判断是否进入故障分类和深度诊断”说明通过通用检查标题旁图标点击呈现，不常驻展示。
14. 页面不常驻展示“异常后按故障分类匹配深度诊断步骤指导”文案；深度诊断步骤指导仅在一级分类、二级分类、故障现象均选定后展示。
15. 附件上传支持 jpeg / jpg / png / pdf，单个文件不超过 50M。
16. 车内（低压上电）检查对应标签包括：低压电气—12V电源网络、智能座舱/车联网全部症状、车身附件全部症状、空调全部症状。
17. 深度诊断按步骤指导记录检查步骤、发现问题、证据材料和最终诊断结论；技师执行深度诊断时可点击上传照片，新增现场照片、测量照片或诊断报告的附件标签，并展示上传成功反馈。
18. 预诊完成后，将深度诊断结论整理为转工单故障现象，带入维修工单。
19. 保存不要求完整检查结论；提交预诊要求通用检查结果、异常时的故障分类、附件、至少一条诊断过程记录和最终诊断结论。
20. 创建页车主车辆信息主信息带、按钮位置与维修工单管理保持一致，关联预约单仅展示第一条匹配数据且不展示匹配依据。
21. 车辆主信息带中的预约单号链接点击后打开预约单详情弹窗，展示基本信息、客户信息、车辆信息和服务信息。
22. 预诊完成后可进入待转工单状态。

## 5. 视觉约束

- 使用 `repair-workorder-m02` 的后台三段式结构：左侧导航、顶部 Tab、主内容区
- 使用相同字体栈：MiSans、PingFang SC、Microsoft YaHei、Arial
- 使用主色 `#2251ff`，浅蓝卡片、白底卡片、细边框和紧凑表格
- 表格、按钮、状态标签、弹窗、查询条尽量复用维修工单管理样式
- 列表页筛选区采用与维修工单管理一致的上下结构：上方为 5 列查询项网格，下方为查询 / 重置操作栏
- 创建页的“车主车辆信息”卡片与维修工单管理保持布局一致
- 创建页“客户问题”卡片布局在“预诊基础信息”下方，不采用左右分栏
- 创建页顶部仅保留标题和操作按钮，不渲染额外说明性文案
- 页面最小宽度按后台系统处理，表格允许横向滚动

- 车辆：沪A·88888 / LFV2A21K0N3456789 / FR神行者8
- 预约单：YY-20260527-018 / apollo / 待到店

- 问题分类：智能座舱/车联网 / 屏幕/显示 / 车机屏幕黑屏

- 深度诊断步骤指导：接车区确认症状操作、座舱功能复现与日志采集、软件版本与显示链路确认
- 诊断过程：通用技术检查、异常故障分类、深度诊断记录
- 技师记录：智能座舱技师过程记录、深度诊断照片、最终诊断结论

## 7. 验收要点

1. 原型可通过 `/prototypes/pre-diagnosis-order-management` 访问。
2. 页面包含预诊单列表、创建预诊单、预诊单详情三类核心视图。
3. 列表支持车牌号、VIN码、客户拆分筛选、状态统计、查看详情和进入创建页，筛选区采用参考维修工单管理的 5 列上下结构。
4. 创建页车辆查询条与维修工单管理一致：车牌查询、VIN 输入、“按 VIN 查询车辆”。
5. VIN 查询弹窗包含车辆查询和车辆精确查询两个 Tab。
6. 车辆查询结果可选择并回填客户车辆信息。
7. 查询车辆后能展示预约单入口，并通过右上角“关联预约单（N）”打开车辆信息弹窗内的第一条候选预约单完成带入，弹窗不展示匹配依据。
8. 未命中预约单时仍在同一创建页继续手工填写。
9. 创建页顶部仅保留面包屑，不展示标题 Hero、英文说明和顶部右侧保存 / 提交预诊按钮；保存 / 提交预诊仅在动态吸顶操作条中展示，车型名称展示为 FR神行者8。
10. 创建页服务方式仅展示自驾到店、救援、取车到店。
11. 创建页能展示接待区和车内（低压上电）检查、是否异常 Radio，并在两个检查分组下方分别展示一级分类、二级分类、故障现象、附件上传；深度诊断步骤指导仅在三项分类/现象选定后呈现，通用技术检查说明通过图标点击呈现。
12. 创建页可体现诊断过程节点、执行人、发现问题、证据材料、技师记录、深度诊断照片上传、上传成功反馈、最终诊断结论填写和转工单故障现象预览。
13. 附件上传提示为支持 jpeg / jpg / png / pdf，单个文件不超过 50M。
14. 详情页展示状态进度、基础信息、客户问题、通用检查、故障分类、附件、深度诊断、诊断过程、技师记录、转工单故障现象和处理记录。
15. 创建页车辆主信息带右上角展示委托书履历、车辆权益、服务活动 / 品质改善、维修建议、车主车辆信息变更入口；预约单、权益、活动/品质改善、维修建议与维修工单管理一样按对应入口打开车辆信息弹窗。
16. 创建页预诊基础信息区不展示预约单摘要条；点击车辆主信息带中的预约单号可打开预约单详情。
17. 预诊单详情状态节点轴采用维修委托书详情页同款圆形节点和横向连线样式。
18. 列表行操作展示“编辑”，已完成状态无编辑按钮。
19. 代码通过 TypeScript 检查。
20. `check-app-ready` 返回 READY。
